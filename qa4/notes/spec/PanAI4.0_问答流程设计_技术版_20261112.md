## 零、4.0 问答所要达到的（Srey 原文）

### 一、目标

4.0 问答要做的，不是比 3.0 进步一点，而是能解决复杂、实用、最需要的问题，作出最优秀的回答。对众弟兄姊妹有实际性的帮助，更实用。

别的职事信息问答也能答真理问题，我们的优势在于：资料最齐全、回答忠于圣经与职事、质量最高，让人一有问题就来问。

### 二、贯穿所有题型的四条要求

- 忠于圣经与职事的话，必须有可核对的出处。
- 站在已过一百年的根据上（职事信息 70 年，节期纲目 30 年）。
- 资料齐全完整。
- 研究所级别的回答。

### 三、要解决的问题，分三大块

- 指明具体对象的：某一篇信息、某一首诗歌、某一节经文等，直接调取原文，不经改写。
- 真理与主题类：现有的九类（待讨论），加上高层次的综合问答，例如跨来源、跨作者的比较与关联。
- 召会生活类（新增）：
  - 范围：基督徒生活、召会生活里实际会遇到的疑难杂症。
  - 做法：拆成子问题，分别找材料，再合起来。
  - 回答：以职事的原话为主，加简单的过渡和归纳。职事没有直接讲到的部分，如实说没有。
  - 例①：弟兄姊妹离婚了还可以擘饼吗？
  - 例②：提前五19 “对长老的控告，除非凭着两三个见证人，你不要接受。”，加二11 “但矶法来到安提阿的时候，因他有可定罪之处，我就当面抵挡他。”；有人说，在召会里负责弟兄犯了道德上的罪，那根据圣经，要在聚会中当面责罚吗？

（注：Srey 后来说明，「复杂」是用户这一个问题的属性，不是召会生活类独有；召会生活类的问题也可能很简单，不拆。见第 3 步。）

## 一、范围与原则

- 【已定】只设计问答一面（back_qa + front_qa + 共享层 back_shared 中与问答相关的部分），不涉及主站 Pansearch。
- 【已定】当前阶段是纸面设计；3.0 只改提示词和小的前端问题。【11-16 更新】后端已在 `qa4/backend` 本机开发，阶段 0、1 已完成；【11-17 更新】阶段 2、3 也已完成，见后端构建方案。
- 【已定】4.0 问答与 3.0 问答、与各版本纲目相互独立：
  - 数据层：4.0 有自己的 Neo4j（qa4-neo4j）和 ES（qa4-es，127.0.0.1:9202）。
  - 部署层：独立于旧服务，目录 /opt/qa4_repo（sparse clone）、/opt/qa4_data、/opt/qa4_transfer。
  - /opt/pansearch/code 是旧站，4.0 不读取、不改动。
- 【已定】模型分工：
  - Haiku 5.5：第 2 步追问改写、第 3 步分类与拆子问题、第 4 步提取明说的词、第 7 步把关。
  - Sonnet 5.5：第 5 步推荐重点、第 8 步生成。
  - 第 1、6、9 步不用对话模型。
  - 模型名放配置，并写入日志与缓存键。第 3、4 步若 Haiku 准确率不够，再改用 Sonnet 5.5。
  - 【11-16 更新】模型调用的实测约束：不传 temperature（新模型只接受默认值）；不支持预填；没有 response_format，JSON 靠提示词与解析；Haiku 要传 `thinking: {"type":"disabled"}`，Sonnet 默认不传；`stop_reason` 不是 `end_turn` 视为失败；每次校验响应的 model。细节见后端构建方案第十节。
- 【待核实】3.0 当前线上模型：据说是 Sonnet 4.6 + Haiku 4.5（代码默认值与此是否一致，未在线上核对）。
- 【已定】两条贯穿原则：
  - 模型自己的知识，只能用来决定「去哪里找」，不能用来决定「说什么」。回答的内容只来自检索到的原文。
  - 原话与归纳分开标注：归纳的每一句，都要能对应到前面引出的原文；没有就说没有。
- 【已定】复杂问题拆子问题（见第 3 步）。拆不拆看用户这一个问题，不看题型。

### 2.6 纲目侧「从题目到推荐重点」现行做法（供参考，不是本设计）
来源：Srey 上传的纲目侧文档（新测试台现行做法，按代码整理，2026-11-12）。本节只摘与问答第 4、5 步有关的部分。

- 流程：两步各调一次模型，都用 Opus 5.5。第一步按题目、纲目性质和负担的重点生成「负担说明」（可跳过）；第二步推荐重点，输出四层词和 0–3 个关键圣经节，程序核对后交人工取舍。
- 推荐重点的输入：纲目主题；纲目性质（五选一：综合性 / 真理启示 / 内在素质 / 生命经历 / 实行应用）；负担说明；可选概念列表（2,239 个）；最内在词库（133 个）。
- 模型设置：Opus 5.5，temperature 0，开思考，输出上限 16,000 tokens。
- 输出：一个 JSON，六项：revelation、intrinsic_essence、experience、practice、summary（一句小结）、key_verses（0–3 节）。
- 程序核对：词不在对应名单里的丢掉（启示、经历、实行三层要在 2,239 个里，内在素质层要在 133 个里）；按纲目性质截上限，总数不超过 20；关键圣经节去重，最多 3 节。
- 各层上限（启示 / 内在素质 / 经历 / 实行）：
  - 综合性：6 / 5 / 5 / 4
  - 真理启示：8 / 4 / 4 / 4
  - 内在素质：4 / 8 / 4 / 4
  - 生命经历：4 / 4 / 8 / 4
  - 实行应用：4 / 4 / 4 / 8
  - Prompt 里写的范围有下限，程序不检查下限；示例里有某一层为空的。
- 选词规则（Prompt 二）：
  - 经历与实行按「发起方是谁」区分：发起方是神、灵、基督，信徒是承受方 → 经历；发起方是信徒本人、主动做 → 实行。
  - 实行「先专后通」：优先从主题、负担说明、已选词直接推出的专属实行词，通用词（如操练灵）只作兜底。
  - 按语义不按字面；每个词必须逐字存在于对应名单；不选放到任何主题都适用的泛词；各层之间不重复。
  - 「高峰真理」18 条是思想浓度参考，不是挑词菜单。
- 用量（最近 11 次中位数）：输入约 19,400 tokens（大半是 2,239 个词的名单），输出约 1,500 tokens，约 $0.11，约 15 秒；推荐重点不读缓存。
- 这份文档里没有第 4 步（字符串匹配、取定义）的做法。

### 第 3 步：问题理解与分类（Haiku 5.5）
- 3.0 现状：Haiku 分三类（一般/定向/经文）；定向识别靠代码规则（_detect_targeted）。
- 4.0 加了什么：

**一次调用的输出**
- 【已定】主类型（一种）。
- 【已定】限定：作者、年代；来源名（生命读经、节期纲目等）若出现，需标明角色是「限定」还是「对象」（见下）。
- 【已定】复杂标记；复杂时输出子问题（每个带题型，可带来源范围、角度）。
- 【已定】敏感或辩证标记。
- 【已定】理解说明（没把握时用，回答开头交代）。

**七种定向**
- 取具体对象（五种，不经检索，直接取）：生命读经（某卷某篇）、节期纲目（某年某次特会的某篇）、注解（某节经文的注解）、诗歌、经文。
- 限定（两种，叠加在一般类之上）：按作者、按年代。【暂定】作者、年代的问题，沿用所属那一类的各层个数，待 Srey 确认。

**十种一般类**
- 定义、比较、个人经历、团体实行、召会生活、汇集、核实说法、反找经文、发展、默认。
- 【已定】个人经历、团体实行、召会生活三类分开，不合并。
- 召会生活：
  - 范围：基督徒生活、召会生活里实际会遇到的疑难杂症。
  - 与另外两类的界线，写入分类提示词时用例子说明，不用词表：个人经历问怎样经历某件事；团体实行问召会怎样实行某件事；召会生活问处境里该不该、能不能、怎么处理。
  - 召会生活类的问题不一定复杂，不一定拆。
- 汇集的定义【已定】：把职事里关于某个主题的话集中起来看，取量大，按出处分组列出，不展开议论；汇集经文不属于汇集，归反找经文。
- 汇集与默认的界线【已定，写入分类提示词时用例子说明，不用词表】：用户明显要把话集中起来看（汇集、整理、职事怎么讲某个主题）→ 汇集；只问一个词或一般问题 → 默认。列举并入默认（把单个词改写成「X有哪些」）。
- 【暂定】跨来源、跨作者的综合问答不单列题型：走「拆子问题」，其中比较类的做法（两边各找，再说区别）推广到来源或书系。

**复杂问题与拆子问题**
- 【已定】复杂与否看用户这一个问题，由第 3 步判断，与题型无关。
- 判断标准：只用同一批材料、同一个角度能不能答完整。
  - 答不完整 → 复杂，拆：涉及两个以上的对象、来源或时期；或带处境，需要原则、经文、实行几方面一起看。
  - 答得完整 → 不拆：只围绕一个主题、一类材料。
- 【已定】拿不准时不拆，由第 7 步放宽重试补救。判断准确率待测试。
- 【已定】子问题最多 4 个。
- 子问题的内容：
  - 题型（决定该子问题各层的侧重）；
  - 来源范围（可选，如只查节期纲目、只查职事信息正文）；
  - 角度（可选）；
  - 是否综合性。
- 综合性子问题（如关联、区别）不单独检索，由第 8 步用前面子问题的材料综合，并标为归纳。成立的前提是它依赖的子问题都至少有材料。
- 召会生活类被判为复杂时，拆分的四个角度：经文根据、真理原则、召会处理与实行、个人经历与操练。角度只在拆分时使用，没拆就当一个问题处理。【暂定：角度草案，用真实问题打磨】
- 问题本身带经文出处的，其中一个子问题走经文通道，取职事对那节的讲论。默认检索库不含圣经索引（已定）。

**限定词的角色**
- 【已定】作者、年代、来源名在问题里有两种角色：
  - 起限定作用：如问某位弟兄怎样说到某个主题，这位弟兄是范围，不是重点。
  - 是问的对象：如要求介绍某位弟兄；或比较两部书。这时它是要问的东西，进第 4 步的第 1 层，也不作硬性过滤。
- 拿不准时按「对象」处理，保留在第 1 层：多一个词只多一路检索，漏掉对象则整个回答偏离。
- 比较两部书这类问题，不能按「取具体对象（某一篇）」处理，归第 3 步分类判断。

**限定的规则（沿用 11-11 版）**
- 作者限定：倪→只查 cwwn；李→cwwl＋text_life＋text_others；注解不参与；纲目与节期默认不参与作者筛选。
- 年代限定：只对 cwwl 生效，用 42 行年代表；61 个无年代书名永不参与；回答里说明所涵盖的册的年份范围；倪文集无年代，如实说明。
- 冲突（倪＋年代；节期＋作者）：直接告知用户职事信息里没有。
- 没把握时不硬限定，回答开头说明对问题的理解。
- 节期的说法：七次特会、一年七次、节期特会等都当作整个节期纲目；春训、秋训指春季、秋季长老训练；夏训指夏季训练。
- 诗歌：大本与补充本都覆盖，默认大本（实现时的默认值）。
- 经文类沿用 3.0 的经文通道和两套识别，不改；【11-16 更新，已定】规则解析采用 get_vers v2.1（探测显示它对「诗八九26」这类简称加中文章写法远强于 3.0 的解析器；各来源的覆盖率见后端构建方案第七节）；整章不设上限。
- 注解：指定经节的，用 3.0 的 bible_data 数据；按主题的，走 map_note（覆盖约 48%）。
- 敏感或辩证是标记，不是题型。
- 个人经历、团体实行、召会生活：提示词里用例子说明，不用词表。

- 因此有的功能：按作者、年代、生命读经、节期、注解、诗歌取内容；各题型有专门做法；复杂问题能分角度、分来源取材。
