## 二、层级判定

这是全篇最容易出错的地方，两批共有 **7 个层级**，且样式名不统一。采用**双轨判定**。

### 2.1 轨一：样式名映射表

| 2 | 一、二、三 | `3中点`、`中点`、`012中点`、`02中题`、`13中点`、`括号中点` |

| 6 | （1）（2） | `7（1）` |
| 7 | （a）（b） | `8（a）` |

### 2.2 轨二：段首文字编号

A 批有 2,154 个文件**完全没有层级样式**，纲目点一律是 `Normal`，层级信息写在段首：格式为 `编号 + Tab + 正文`，如 `壹→罪的结果是与神分开……`。这一轨是必须的，不能省。

取第一个 Tab 之前的文字作为 `label`，按下表定级：

| 层级 | 编号字符 |
|---:|---|
| 1 | 壹 贰 叁 肆 伍 陆 柒 捌 玖 拾 |
| 2 | 一 二 三 四 五 六 七 八 九 十 十一 …（含「百」） |
| 3 | 阿拉伯数字 1 2 3 … |
| 4 | a b c … z |
| 5 | （一）（二）… |
| 6 | （1）（2）… |
| 7 | （a）（b）… |

### 2.3 异体归一（在判定前先做）

实测存在下列异体写法，先归一再判定：

| 异体 | 归一为 | 出现处 |
|---|---|---|
| 全角字母 `ａｂｃｄ…` | 半角 `abcd…` | 两批，第 4 级 |
| `㈠㈡㈢㈣` | `（一）（二）…` | 两批，第 5 级 |
| `⑴⑵⑶⑷⑸` | `（1）（2）…` | 两批，第 6 级 |
| `(一)` `(1)` `(a)`（半角括号） | 全角括号形式 | 两批 |
| `貳` | `贰` | A 批 |
| `参` | `叁` | A 批 |
| `拾参` `贰一` 等组合 | 按首字定级 | A 批 |
| `aa` `bb` `cc` … `ll` | 第 4 级（字母用尽后的续编） | A 批 |

### 2.4 双轨的合并规则

1. 两轨都命中且层级相同 → 采用，`level_source = "both"`；
2. 只有一轨命中 → 采用该轨，`level_source = "style"` 或 `"text"`；
3. 两轨都命中但**层级不同** → 以**样式轨**为准，同时把该段写入异常清单（第七节），供人工复核；
4. 两轨都不命中 → 见 2.5。

### 2.5 无编号的纲目点

确实存在没有编号的纲目点，不能当噪音丢掉：

- **A 批「前言」**：516 段，样式 `2大点`，位置在读经之后、「壹」之前。按**样式轨**定为第 1 级，`label` 记为「前言」。
- **B 批【纲目的原文】**：实测**没有**「序言」「前言」（那些在复合版和听抄稿版里），只有「添言」1 段、「附：」4 段。

规则：**段落样式属于层级样式表** → 即便段首无编号，也按样式定级，`label` 取段首文字（到第一个 Tab 或标点为止）。

若既无层级样式、段首又无编号 → 不是纲目点，跳过并计入统计。

## 三、截断规则（去掉职事信息摘录）

A 批每篇纲目后面附有整篇职事原文；B 批【纲目的原文】有 33 个文件带附录。两批共用一套规则。

### 3.1 规则

> 自文件开头顺序扫描，遇到**第一个**满足下列任一条件的段落，该段及其后全部丢弃；
> 若整篇没有这样的段落，则全文保留。

**条件 A — 标志文字**（段落文字去掉首尾空白与段内换行后，等于下列之一）：

- `职事信息摘录：`
- `职事信息摘录`（无冒号）
- `职事信息之摘录：`
- `职事信息摘要：`
- `听抄信息：`
- `晨兴圣言信息：`

冒号全角半角均可，句号亦可。

**条件 B — 「附：」开头**：段落文字以 `附：` 或 `附:` 开头。B 批有 4 个文件用此形式（写法各不相同，如「附：李弟兄于一九九七年三月二十四日的交通。」「附：活力排。」）。

### 3.2 已知的例外，需单独处理

**B 批 4 个文件没有任何标志段**，纲目最后一点之后直接接 `0000模板` 引文：

| 文件 | 附录起始段 |
|---|---|
| `1998-02 春季长老训练\02\【纲目的原文】msg. 2 神新约的经纶要使复活的基督得着繁殖…` | 第 65 段 |
| `2020-03 国殇节特会\05\【纲目的原文】msg. 5 答应神的呼召作祂时代的凭借…` | 第 47 段 |
| `2022-02 春季长老训练\02\【纲目的原文】msg. 2 信的内在意义` | 第 58 段 |
| `2025-01 国际华语特会\01\【纲目的原文】msg. 1 罗马书五至八章中的生命线与死亡线` | 第 31 段 |

处理办法：**硬编码这 4 个文件的截断段号**，写在配置里，转换时按段号截断。不要用「最后一个纲目点之后的 0000模板」作为通用规则——B 批另有 28 个文件在纲目内部使用 `0000模板`，通用规则会误截。

**A 批 1 个文件**规则失效（`2 李常受文集纲目\50 …\msg. 2 哥林多前后书中基督作那灵…` 第 41 段，摘录样式被误套在纲目点上）。同样硬编码处理。

### 3.3 不用样式名作截断依据

A 批全量统计：

| 情形 | 文件数 | 若按样式截断的后果 |
|---|---:|---|
| 标志段样式为 `9职事信息摘录`/`职事信息摘录` | 11,474 | 正确 |
| 标志段用了别的样式（`Normal` 等） | 520 | **截不到**，摘录混入纲目 |
| 更早的段落被误套了摘录样式 | 36 | **截早了**，纲目被切断 |

所以文字规则是主，样式仅作辅助校验（两者不一致时写入异常清单）。

## 四、元数据解析

### 4.1 一律从路径和文件名取

A 批有 **6,963 个文件**缺少「0系列／11111西列／00篇题」中的至少一段（占一半以上），样式体系有六套。靠段落取元数据会有一半走兜底。

而路径本身信息完整：

```
A 批：倪李文集纲目\1 倪柝声文集纲目\1 倪柝声文集第一辑第一册，灵修指微\msg. 1 回到十字架罢.docx
     └─ 批次        └─ 类别           └─ 书名                        └─ 篇号 + 篇题

B 批：节期纲目\2003-04 夏季训练\02\【纲目的原文】msg. 2 新约的众执事和他们的职事…docx
     └─ 批次   └─ 特会（年-月 + 名称）└─篇序号  └─版本        └─ 篇号 + 篇题
```

**规则：书名、类别、篇号、篇题一律从路径与文件名解析；段落里的 `0系列`/`11111西列`/`00篇题` 若存在，解析出来放进 `meta.doc_header`，仅作校验与备查，不作为主来源。**

### 4.2 A 批字段来源

| 字段 | 来源 |
|---|---|
| `category` | 一级目录名去掉序号，如「倪柝声文集纲目」→「倪柝声文集」 |
| `book` | 末级目录名（含书名与册次），多层时取最深一层含书名的目录 |
| `book_path` | 从一级目录到文件所在目录的完整目录链（数组） |
| `msg_no` | 文件名中 `msg. N` / `lsn. N` 的 N |
| `msg_label` | `msg` 或 `lsn` |
| `title` | 文件名去掉 `msg. N ` 前缀与扩展名 |

### 4.3 B 批字段来源

| 字段 | 来源 |
|---|---|
| `conference` | 一级目录名，如「2003-04 夏季训练」 |
| `year` / `month` | 从一级目录名前缀解析，如 2003 / 04 |
| `conference_name` | 一级目录名去掉年月前缀，如「夏季训练」 |
| `seq_dir` | 二级目录名（篇序号），如「02」 |
| `version` | 文件名开头的 `【…】`，固定为「纲目的原文」 |
| `msg_no` | 文件名中 `msg. N` 的 N |
| `title` | 文件名去掉 `【…】msg. N ` 前缀与扩展名 |

> B 批特例：`2026-05 秋季长老训练` 目录下 9 个【纲目的原文】直接放在一级目录下，没有篇序号子目录。此时 `seq_dir` 为空，其余照常解析。

### 4.4 篇头（doc_header）

从段落中解析，缺失则留空，不报错：

| 字段 | 来源样式 |
|---|---|
| `series` | 系列／书名类样式 |
| `sub_series` | 子系列／西列类样式 |
| `title_in_doc` | 篇题类样式 |
| `bible_reading` | 读经类样式 |

## 五、非纲目文件的识别与排除

A 批约 **483 个**文件不是纲目：

- **405 个**没有任何纲目点样式，是介言、启事、总目录、诗歌分类、期刊「第N期」等，整篇是正文；
- **78 个**虽有 `3中点` 等样式，但也是期刊、通讯、介言的正文（例如通问汇刊各期通篇用 `3中点`）。

### 5.1 判定条件

转换时对每个文件统计**纲目点数量**（按第二节的双轨判定）。满足下列任一条件 → 判为非纲目文件：

1. 纲目点数量为 0；
2. 纲目点全部为同一层级，且该层级不是第 1 级，且文件无截断标志段（典型的期刊正文特征）。

条件 2 需在首轮转换后用实际数据校准，**初版先只用条件 1**，其余交人工复核。

### 5.2 输出

非纲目文件**不输出到主 JSON**，而是单独输出 `excluded_files.json`，含路径、判定理由、段落数、出现的样式名。**这份清单需人工过目确认后才算定案。**

## 六、输出 JSON 格式

### 6.1 文件

| 输出 | 内容 |
|---|---|
| `outline_12490.json` | A 批全部纲目文件，一篇一条 |
| `outline_feasts.json` | B 批【纲目的原文】，一篇一条 |
| `excluded_files.json` | 被排除的非纲目文件清单 |
| `anomalies.json` | 异常清单（层级冲突、截断异常等） |
| `conversion_report.md` | 转换统计报告 |

每个 JSON 为数组，**每条一行**（便于流式读取与行数核对）。

### 6.3 字段说明

| 字段 | 说明 |
|---|---|
| `id` | 规范化相对路径（去扩展名，分隔符统一为 `/`；B 批去掉 `【…】` 前缀）。**全局唯一、稳定、可读**，是后续 `chunk_id` 的前缀 |
| `batch` | `12490` 或 `feasts` |
| `meta.style_system` | 该文件使用的样式体系（标准／Normal／大点中点小点／t_ 前缀／三位数字／大题中题），便于排查 |
| `points[].idx` | 纲目点在本篇中的顺序号，从 0 起 |
| `points[].level` | 1～7 |
| `points[].label` | 编号原文（归一后），无编号时取段首文字，如「前言」「添言」 |
| `points[].text` | 纲目正文，**不含 label 与 Tab** |
| `points[].style` | 原段落样式名，回查用 |
| `points[].level_source` | `both` / `style` / `text` |
| `points[].para_no` | 原 docx 中的段号（从 0 起），回查用 |
| `stats.truncated_at` | 截断起始段号；未截断为 `null` |
| `stats.truncate_rule` | 命中的规则，如 `text:职事信息摘录：`、`text:附：`、`hardcoded` |

> **B 批的单条结构相同**，`meta` 换成 4.3 节的字段（`conference` / `year` / `month` / `conference_name` / `seq_dir` / `version` / `msg_no` / `title`）。

### 6.4 为什么不用 v7 的 `msg` + `ot1/ot2` 格式

1. `ot1~otn` 的标记体系实际只处理到 4～7 级，v7 的 `process_map_note` 因此**丢弃了 ot5 以下的内容**——这是已发生的 bug；本批数据有 7 个层级，用数字 `level` 无上限。
2. `label`（壹/一/1/a）与 `style` 在 map 格式里会丢失。`label` 是还原纲目体例所需，`style` 是回查线索，一旦不存，以后要用得重跑全量。
3. 4.0 本就与 3.5 分开建索引，没有格式兼容的必要。切块逻辑无论哪种格式都要重写。

**对 ES 检索无影响**：本 JSON 不直接进 ES。链路是 `docx → 本 JSON → chunks JSON（扁平字段）→ ES`，ES 里的字段与 3.5 的 `kg-rag_*` 同构，检索代码无需改动。

## 七、异常清单

转换时把下列情形写入 `anomalies.json`，**不中断转换**，供人工复核：

| 类型 | 触发条件 |
|---|---|
| `level_conflict` | 样式轨与文字轨判定的层级不一致 |
| `level_jump` | 层级跳级（如第 1 级后直接出现第 3 级） |
| `no_level1` | 整篇没有第 1 级纲目点 |
| `truncate_by_style_only` | 有摘录样式段但文字规则未命中 |
| `truncate_text_late` | 文字规则命中的段号晚于某个摘录样式段 |
| `empty_header` | 篇头四项全缺 |
| `unknown_style` | 出现映射表之外的样式名 |
| `unknown_label` | 段首文字既非编号也非已知标签 |

## 八、验证清单

转换完成后，`conversion_report.md` 须包含：

1. **条数对账**
   - A 批：读入 12,509，排除非纲目 N 个，输出 M 条，`12509 = N + M`；
   - B 批：读入 2,631，输出 M 条，`2631 = M`（若有排除须列明）。
2. **层级分布**：每批各级纲目点的数量与占比，按 level 1～7 列表。
3. **token 分布**：以「一个第 1 级点 + 其下属所有层级」为单位，统计 min / max / avg / median，以及 <150、150–800、>800 三档的数量与占比。**这是后续定切块规则的依据。**
4. **截断统计**：命中各条规则的文件数；未截断的文件数；硬编码处理的文件数。
5. **异常统计**：各类异常的数量，`anomalies.json` 行数与之相符。
6. **抽样比对**：两批各随机抽 10 篇，逐条列出 JSON 的 points 与原 docx 的段落对照，确认层级、label、text 完全正确。
7. **唯一性**：`id` 无重复。
8. **完整性**：随机抽 20 篇，核对 `stats.para_outline` 与 points 数组长度一致；核对最深层级的点没有丢失（特别是第 5～7 级）。
